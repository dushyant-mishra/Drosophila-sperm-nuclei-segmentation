# Finding: the stratified body-width evidence cannot reflect pipeline changes

Date: 2026-09-15
Raised by: Claude while attempting to regenerate evidence after the measurement changes
Status: open, no code change made
Affects: `MEAS-BODY-WIDTH-001` visual evidence, and any reviewer who reads
`audits/evidence/v571_body_width_stratified_20260908/` as current

## What happened

The stratified body-width evidence predates both the profile isolation fix and
evidence-based merge splitting, so it was regenerated on commit `48977a3`. The
output was identical to the 2026-09-08 run: the same sixteen tracks, the same
track ids, and the same widths to four decimals, despite substantial changes to
segmentation and measurement in between.

## Why

`scripts/generate_v571_body_width_evidence.py` takes its track selection, its
categories and its reported widths from a frozen replay archive:

```python
tracks = read_replay_table(archive, stem, "track_summary")
detections = read_replay_table(archive, stem, "tracked_detections")
```

The archive is
`audits/evidence/v571_rc6_candidate/provenance/tracking_replay_inputs_outputs.zip`,
9.0 MB, last changed in git on 2026-08-27. The script does re-run
`segment_slice`, but only to render the mask images. Every number it reports
comes from the archive.

The consequence is that this generator can never show a measurement change. Its
figures will keep matching the August archive no matter what the pipeline does,
while the manifest records the current commit hash, which invites a reviewer to
read the output as evidence for that commit.

## What was done

The regenerated directory was deleted rather than committed. A dated evidence
folder stamped with commit `48977a3` but containing numbers from an August
archive is worse than no new folder at all, because it looks current.

No code was changed. Rebuilding the archive means re-running the two-specimen
pilot, which produces new numbers, and the owner has asked to review how the
pipeline is run before any further run happens.

## What this does and does not invalidate

The existing 2026-09-08 stratified evidence remains valid as evidence for
`MEAS-BODY-WIDTH-001` as that claim stood in August. It is not evidence for the
current pipeline and must not be cited as such.

`MEAS-INTENSITY-WIDTH-001` is unaffected. Its visual evidence in
`audits/evidence/v571_intensity_width_visual_20260914/` is generated by
`scripts/generate_v571_intensity_width_evidence.py`, which segments each plane
fresh and reads every number from that segmentation, with no replay archive
involved.

## Options

1. Rebuild the replay archive from a fresh two-specimen pilot, then regenerate.
   This is roughly thirty minutes of CPU and is the only way the existing
   generator can show current behaviour.
2. Change the generator to measure from fresh segmentation, as the
   intensity-width generator already does, and keep the archive only for
   provenance. This removes the trap permanently.
3. Retire the stratified generator once `MEAS-BODY-WIDTH-001` is formally
   superseded by `MEAS-INTENSITY-WIDTH-001`, since the mask chord is now a
   technical diagnostic rather than the biological width.

Option 2 is the durable fix. Option 3 may make it unnecessary.
